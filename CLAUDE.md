# Uniform

Uniform: it's us studio's design system. One repo:

- `uniform/`: the `studio-uniform` gem. A Rails engine that serves `assets/uniform/` (CSS, `uniform.js`, fonts, icons) through Propshaft, plus `mailers/` and tests. Only this folder ships.
- Everything else: the Bridgetown docs site. It loads the gem with `gem "studio-uniform", path: "uniform"` and reads files through `Studio::Uniform.assets_path` and `Studio::Uniform.mailers_path`. NEVER hard-code a path into the gem.

Design rules: [Rules](/start/rules/) (`src/_data/rules.yml`).

## Where things go

- Component behaviour: `uniform/assets/uniform/uniform.js` only. New element: one entry in `src/_data/elements.yml` per `define(...)`, and add it to the `display` rule at the end of `base.css`.
- New component adapted from another library (shadcn and others): use it for anatomy and ARIA only. NEVER copy its class names, sizes or colours.
- Docs-only CSS: `frontend/styles/site/`, layer `site`. NEVER in the gem. Docs dogfood Uniform: docs class only when Uniform has nothing.
- Docs scripts: `frontend/javascript/index.js`. Edit in place, NEVER overwrite.
- Rules, classes, elements: `src/_data/*.yml`. NEVER write a rule or class description in a page.
- `/llms.txt` is generated by `src/llms.erb` from nav, data files and front matter. Change the data, NEVER the output.
- `/writing/` is a summary of the studio writing style for people. NEVER add writing rules there.

## Traps

- `classes.yml`: `page` is never a pattern. NEVER write "Sites only" in a description (`scope: sites` shows the chip). NEVER start a description with a number + full stop (Markdown makes a list).
- Patterns add no classes and no Uniform CSS. Can't build it from what exists: build the missing component first.
- Task routes only link nav pages (titles come from `navigation.yml`).
- Every nav page needs a front matter `summary`, or llms.txt falls back to the first paragraph.
- Live examples: one partial in `src/_partials/examples/` renders the example and its code block. Indent 2 spaces per level: the code block shows the file as written.
- An HTML code block followed by an ERB one becomes HTML/Rails tabs, from `plugins/builders/code_tabs.rb`. NEVER build the tabs by hand.
- Screen frames only set width. App shell, Auth shell, Site header, Grid, Description list use container queries. NEVER fake a breakpoint.
- Mailers can't use Uniform CSS: `role="presentation"` tables, inline styles, Helvetica/Arial and Menlo, hex from tokens, plain-text version.
- Uniform reads as if every decision was made on purpose from the start. NEVER document what was tried, old class names or how it used to work.
- The human runs the dev server (`bin/bridgetown start`, port 4000).
